## Goal
When a PR that bumps `package.json` version merges to `main`, CI tags `vX.Y.Z`, creates a GitHub release and publishes `hoo-discord-bot` to npm (using the `NPM_TOKEN` secret). `/pr` gets the working tree into a PR, and `/postmerge` checks the release and returns to `main`.

## New files

### `.github/workflows/ci.yml`
- Triggers: `pull_request` and `push` to `main`.
- Job `check`: checkout, `oven-sh/setup-bun@v2`, `bun install --frozen-lockfile`, `bun run typecheck`, `bun run test`, `npm pack --dry-run` (checks the tarball contents).

### `.github/workflows/release.yml`
- Trigger: `push` to `main` plus `workflow_dispatch` (for manual retry). `concurrency: release`.
- `permissions: contents: write, id-token: write` (provenance).
- Steps:
  1. checkout with `fetch-depth: 0`, setup-bun, `actions/setup-node@v4` with `node-version: 22`, `registry-url: https://registry.npmjs.org`.
  2. Read `VERSION` from package.json, then `TAG=v$VERSION`.
  3. Guard: if `git rev-parse $TAG` exists **and** `npm view hoo-discord-bot@$VERSION version` returns it, set `skip=true` and stop. Each later step is idempotent, so a half-failed run can be re-run.
  4. `bun install --frozen-lockfile`, typecheck, unit tests.
  5. If the tag is missing: `git tag $TAG && git push origin $TAG`.
  6. If the GitHub release is missing (`gh release view $TAG` fails): `gh release create $TAG --generate-notes --verify-tag` (env `GH_TOKEN: ${{ github.token }}`).
  7. If the npm version is missing: `npm publish --provenance --access public` (env `NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}`).

### `.cortexcode/prompts/pr.md` (the `/pr` command)
Frontmatter `description: Commit everything to a branch, push, open/update PR`. It takes an optional argument (`$ARGUMENTS`): a branch name or a `patch|minor|major` bump. The agent does these steps:
1. `git fetch origin`. If on `main` (or detached), create a branch: use the arg, or derive `feat/<slug>` from the diff. If the branch exists locally or remotely, check it out or reuse it.
2. Safety check before staging. Abort if a staged path matches `.env`, `*.pem` or `*token*`, or the diff contains secrets. Rely on `.gitignore`.
3. Ask (or use the arg) whether this PR releases. If yes, run `npm version <bump> --no-git-tag-version` so CI does the tagging.
4. Run `bun run check`. Stop on failure and report it.
5. `git add -A`. Commit with a conventional message written from the diff. Skip if there is nothing to commit.
6. `git push -u origin <branch>`.
7. If `gh pr view` finds no PR, run `gh pr create --base main --fill` (title and body from the commits, plus "Release: vX.Y.Z" if bumped). If a PR exists, print its URL.
8. Print the PR URL and the `gh pr checks` status.

### `.cortexcode/prompts/postmerge.md` (the `/postmerge` command)
Frontmatter `description: Verify npm + GitHub release after merge, return to main`. Steps:
1. Find the PR for the current branch with `gh pr view --json state,mergedAt,number`. If it is not `MERGED`, stop and report.
2. `git fetch origin --tags`. Read `VERSION` from `origin/main:package.json`.
3. Find the release workflow run for the merge commit: `gh run list --workflow release.yml --commit <mergeCommit>`, then `gh run watch` until it finishes. If it failed, show `gh run view --log-failed` and stop (stay on the branch).
4. Check:
   - the `v$VERSION` tag exists on origin (`git ls-remote --tags origin v$VERSION`);
   - `gh release view v$VERSION` succeeds;
   - `npm view hoo-discord-bot@$VERSION version` equals `$VERSION`. Retry about 5 times, 10 s apart, because the registry lags.
   If the PR did not bump the version, report "no release in this PR" instead of failing.
5. If everything is OK: `git checkout main && git pull --ff-only`, delete the merged local branch (`git branch -d`), `git remote prune origin`.
6. Print a summary table (tag / GH release URL / npm URL / branch).

## Risks
- `NPM_TOKEN` must be an **Automation** or granular token with publish rights, otherwise 2FA blocks CI publishing.
- First publish claims the name `hoo-discord-bot` publicly. The source is under MIT, which matches the LICENSE.
- The bin runs `.ts` directly, so users must have Bun installed.
- The repo must allow Actions to create tags and releases (Settings → Actions → Workflow permissions: read/write). Otherwise tag push fails. The workflow sets `permissions:` explicitly.
